# Исследование хранилища UGC

Сервис UGC хранит оценки фильмов, закладки, рецензии и голоса за рецензии.
Главный критерий выбора — скорость чтения: целевое время ответа каждого
сценария не превышает 200 мс.

## Вывод

Для измеренных сценариев рекомендуется **PostgreSQL 16**. При одинаковом
наборе данных, индексах и тёплом кэше PostgreSQL показал меньшую p95-латентность
во всех четырёх read-path. MongoDB 8 также значительно укладывается в цель
200 мс и подходит, когда приоритетом являются гибкая схема документов и
независимое горизонтальное масштабирование. Однако эти преимущества не
перевешивают измеренное отставание по главному критерию этой задачи.

Отдельный UGC-сервис предпочтительнее расширения уже существующего: нагрузка на
пользовательский контент, его индексы и жизненный цикл развёртывания изолированы
от каталога фильмов. Цена решения — отдельные контейнеры, бэкапы, мониторинг и
согласованность UUID-ссылок на пользователей и фильмы.

## Модель данных и индексы

В обеих БД сформирован одинаковый набор из **10 000 001** логической записи:

- оценки: пользователь, фильм, оценка `smallint` от 0 до 10, дата;
- закладки: пользователь, фильм, дата;
- рецензии: идентификатор, пользователь, фильм, текст, авторская оценка,
  полезность и дата;
- голоса за рецензии: пользователь, рецензия, `-1` или `1`;
- `rating_summaries`: одна предрассчитанная сводка на фильм.

Индексы покрывают фильтрацию и сортировку: `(user_id, created_at)` для оценок
и закладок, `film_id` для оценок, а также `(film_id, created_at|author_score|
vote_score, id)` для рецензий. Сводка хранит `score_count`, `score_sum`,
`likes_count` и `dislikes_count`; поэтому её чтение не агрегирует миллионы
исходных оценок.

## Стенд и запуск

Требования: Docker Desktop, Python 3.12 и драйверы из
[`research/requirements.txt`](requirements.txt).

```powershell
cd ugc_service
python -m pip install -r research\requirements.txt
docker compose -f research\docker-compose.yml up -d

# MongoDB: для доступа с Windows используйте published port, а не имя mongo.
$env:MONGO_URI = 'mongodb://localhost:27017/?directConnection=true'
$env:POSTGRES_DSN = 'postgresql://ugc:ugc@localhost:5434/ugc'

python research\generate_data.py --target mongo --records 10000001 --seed 42
python research\generate_data.py --target postgres --records 10000001 --seed 42

python research\benchmark_reads.py --target mongo --iterations 1000 --output research\mongo-optimized-results.json
python research\benchmark_reads.py --target postgres --iterations 1000 --output research\postgres-optimized-results.json
```

## Методика

Для каждой БД генератор использует одинаковый seed `42` и распределение данных.
Каждый read-path выполняется 1000 раз. Замер охватывает время выполнения запроса
и чтения результата в драйвере клиента. Кэш — тёплый: тест запускался после
загрузки данных, без перезапуска контейнеров. Поэтому показатели отражают
сравнение индексированных запросов на локальном стенде, а не сетевую latency
production-кластера.

## Результаты

Все значения — миллисекунды, 1000 запросов, тёплый кэш.

| Сценарий | PostgreSQL mean / p50 / p95 / p99 | MongoDB mean / p50 / p95 / p99 |
| --- | ---: | ---: |
| Список оценённых пользователем фильмов | 1.112 / 1.029 / **1.419** / 2.238 | 1.531 / 1.440 / **1.870** / 2.445 |
| Сводка оценки фильма из `rating_summaries` | 1.032 / 0.986 / **1.350** / 2.109 | 1.410 / 1.348 / **1.852** / 2.537 |
| Список закладок пользователя | 0.949 / 0.921 / **1.142** / 1.425 | 1.449 / 1.357 / **1.976** / 2.846 |
| Рецензии фильма, сортировка по полезности | 1.004 / 0.967 / **1.275** / 1.686 | 1.414 / 1.361 / **1.811** / 2.292 |

PostgreSQL быстрее MongoDB по p95 на 24–42% в зависимости от сценария. При
этом максимальная p99-латентность обеих БД меньше 3 мс, то есть многократно
ниже требуемых 200 мс.
